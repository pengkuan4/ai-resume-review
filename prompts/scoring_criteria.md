# AI 简历诊断评分标准

本文档用于定义 AI Resume Review 的简历诊断评分标准。总分为 100 分，面向计算机相关专业应届生，重点评估简历是否适合技术类初级岗位。

评分应结合简历实际内容，不要只根据关键词数量判断。若简历信息缺失，应在对应项目中扣分，并明确指出缺失内容。

## 总分构成

| 评分项 | 分值 |
| --- | ---: |
| 基础信息完整度 | 10 分 |
| 教育背景表达 | 10 分 |
| 技术栈匹配度 | 20 分 |
| 项目经历质量 | 30 分 |
| 岗位匹配度 | 20 分 |
| 简历表达清晰度 | 10 分 |
| 合计 | 100 分 |

## 1. 基础信息完整度：10 分

### 评分依据

- 是否包含姓名、联系方式、邮箱等基本信息。
- 是否包含求职方向或目标岗位。
- 联系方式是否清晰、专业、便于联系。
- 是否包含必要的在线材料，如 GitHub、个人博客、作品地址等。

### 常见扣分点

- 缺少手机号或邮箱。
- 邮箱命名不专业。
- 没有明确求职方向。
- GitHub、博客或项目地址不可访问，或只写了名称没有链接。
- 基础信息占用过多篇幅，影响重点内容展示。

### 优秀示例

```text
张三 | 后端开发 / DevOps 方向
手机：138xxxx1234 | 邮箱：zhangsan@example.com
GitHub：https://github.com/xxx | 技术博客：https://blog.example.com
```

### 较差示例

```text
张三
电话：无
邮箱：abc123@qq.com
想找一份计算机相关工作
```

## 2. 教育背景表达：10 分

### 评分依据

- 学校、专业、学历、就读时间是否清楚。
- 是否列出与目标岗位相关的核心课程。
- 成绩、排名、奖项是否真实且表达简洁。
- 教育背景是否服务于技术岗位求职，而不是堆砌无关信息。

### 常见扣分点

- 缺少专业、学历或就读时间。
- 核心课程过多，且与岗位无关。
- 奖项描述模糊，无法判断含金量。
- 教育背景内容过长，挤占项目经历篇幅。

### 优秀示例

```text
XX 大学 | 软件工程 | 本科 | 2022.09 - 2026.06
相关课程：数据结构、操作系统、计算机网络、数据库系统、Java Web 开发
```

### 较差示例

```text
XX 学校，计算机专业
学过很多课程，成绩还可以，参加过一些活动
```

## 3. 技术栈匹配度：20 分

### 评分依据

- 技术栈是否与目标岗位匹配。
- 是否区分熟悉、了解、使用过，避免夸大。
- 是否覆盖岗位所需的核心技能。
- 技术栈是否能在项目经历中找到对应使用场景。

不同方向重点参考：

- 后端开发：Java、Spring Boot、MySQL、Redis、接口设计、权限、日志、测试等。
- 测试开发：测试基础、接口测试、自动化测试、脚本能力、CI、缺陷定位等。
- DevOps/SRE：Linux、Docker、Nginx、CI/CD、监控、日志、部署、故障排查等。

### 常见扣分点

- 技术关键词堆砌，但项目中没有体现使用场景。
- 写“精通”但没有对应项目或实践支撑。
- 目标岗位是后端开发，却几乎没有后端框架、数据库或接口经验。
- 目标岗位是 DevOps/SRE，却缺少 Linux、部署、容器、Nginx 或日志相关内容。
- 技术栈过杂，无法判断主攻方向。

### 优秀示例

```text
技术栈：
- Java：熟悉集合、异常处理、面向对象基础，使用 Spring Boot 开发过 REST API
- MySQL：能够设计基础表结构，编写常用查询语句
- Linux：熟悉常用命令，完成过项目部署和日志排查
- Docker / Nginx：使用 Docker Compose 部署前后端服务，并通过 Nginx 配置反向代理
```

### 较差示例

```text
精通 Java、Python、C++、Go、Vue、React、MySQL、Redis、Docker、Kubernetes、微服务、大数据、人工智能
```

## 4. 项目经历质量：30 分

### 评分依据

- 项目背景是否清楚，能否让面试官快速理解项目要解决的问题。
- 个人职责是否明确，能否看出候选人实际做了什么。
- 技术选型是否具体，是否说明为什么使用相关技术。
- 是否体现关键实现、问题解决、测试、部署或优化过程。
- 是否有结果表达，如功能完成情况、稳定性提升、部署简化、可维护性提升等。
- 项目描述是否与目标岗位能力相关。

### 常见扣分点

- 只写项目名称和技术栈，没有说明业务场景和个人贡献。
- 使用“参与开发”“负责部分功能”等模糊表达。
- 项目经历像课程作业说明，缺少工程实践细节。
- 没有接口、数据库、部署、测试、日志等具体实现内容。
- 结果表达为空，无法判断项目价值。
- 项目描述过度夸大，超过应届生合理能力范围。

### 优秀示例

```text
AI 简历诊断网站 | Spring Boot + Next.js + MySQL + Docker
- 负责后端 PDF 上传与解析接口，使用文件类型和大小校验降低异常请求风险。
- 设计 AI 诊断请求流程，将简历文本封装为结构化 Prompt，并返回评分、问题和修改建议。
- 使用 Docker Compose 编排前后端服务，通过 Nginx 配置反向代理，简化本地和服务器部署流程。
```

### 较差示例

```text
简历网站项目
使用 Java 和前端技术完成项目，实现了很多功能，提升了能力。
```

## 5. 岗位匹配度：20 分

### 评分依据

- 简历内容是否能支撑明确岗位方向。
- 技术栈、项目经历和求职意向是否一致。
- 是否体现目标岗位关注的核心能力。
- 是否能让面试官判断候选人适合进入哪类初级技术岗位。

方向参考：

- 后端开发：接口开发、数据库设计、业务逻辑、服务稳定性、测试意识。
- 测试开发：测试用例、接口测试、自动化脚本、缺陷定位、质量保障。
- DevOps/SRE：Linux、部署、Nginx、Docker、CI/CD、日志、监控、故障处理。

### 常见扣分点

- 求职方向不明确，只写“计算机相关岗位”。
- 简历内容与目标岗位脱节。
- 同时写多个方向，但项目经历无法支撑任何一个方向。
- 岗位关键词存在，但缺少实际项目证明。
- 缺少与运维、部署、测试或后端能力相关的具体经历。

### 优秀示例

```text
求职方向：后端开发 / DevOps 方向
项目经历中体现了 Spring Boot 接口开发、MySQL 表设计、Docker Compose 部署、Nginx 反向代理和日志排查。
```

### 较差示例

```text
求职方向：Java、前端、测试、运维、算法都可以
项目经历：做过一个管理系统
```

## 6. 简历表达清晰度：10 分

### 评分依据

- 简历结构是否清晰，模块划分是否合理。
- 语言是否简洁、准确、专业。
- 项目描述是否使用动作和结果导向表达。
- 是否避免错别字、口语化、重复内容和无意义形容词。
- 一页或两页内是否突出重点内容。

### 常见扣分点

- 大段文字堆叠，缺少分点。
- 表达过于口语化，如“学到了很多”“负责了一些功能”。
- 多处错别字或格式不统一。
- 使用大量空泛词汇，如“熟练掌握”“精通”“有较强能力”，但没有事实支撑。
- 重要项目被无关内容挤占。

### 优秀示例

```text
- 基于 Spring Boot 设计简历上传接口，完成 PDF 文件校验、文本解析和异常处理。
- 使用 Docker Compose 编排前后端服务，配合 Nginx 实现统一入口访问。
```

### 较差示例

```text
我在这个项目中学到了很多技术，也做了很多功能，感觉自己能力提升很大。
```

## 评分解释建议

AI 输出最终评分时，应同时给出：

- 总分
- 各项得分
- 扣分原因
- 最优先修改的 3 个问题
- 最能提升岗位匹配度的修改建议
